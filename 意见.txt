 看完这份文档，我的判断是：**这是完全可行的，而且可能比 2.1.16 的位置固定度更优雅、更贴近你心中的理想模型。**

你的直觉很对——2.1.16 的 `pos-fixed` 本质上是一个**针对标题语料特殊形态的补丁**（"句首/句末的低熵是位置假象"）。它有效，但不够内禀。而**有向依赖关系（子串-超串的层级结构）**是 BFS 生长算法**天然就有的信息**，不需要从文本外部（标点、行首、行尾）借假设。

---

## 核心思路：用「结构归属」替代「位置豁免」

2.1.11 的复合熵回答的是：**这个词在文本流中的邻居自由不自由？**

但它无法区分两种「低熵」：
- **真依附**：`之魂` 右侧总是 "X之魂" 的句末，左侧总是某个名字 → 低熵是真依附
- **位置假象**：`什么鬼` 右侧总是空/PUNCT（标题末尾），但它本身是个完整的语义单元 → 低熵是假象

2.1.16 用「位置固定度」区分这两者：如果一侧 80% 是空/符号，就认为是「位置使然」而豁免。

**有向依赖的等价思路是**：如果这个词在**词汇层级**中是一个**结构顶端**（不被任何更长真词覆盖，或覆盖它的超串极度分散），那么它的低熵就不是真依附，而是表层位置的副产品。

---

## 具体指标：结构归属熵（Structural Belonging Entropy, SBE）

在 2.1.11 的 `count / independent` 基础上，再进一步，记录每个词被**哪些超串**覆盖：

```
对于候选词 W：
  - 设 Super(W) = 候选池中所有包含 W 的超串
  - 设 cover_count(W, S) = W 在语料中作为 S 的子串出现的次数
  - 设 independent(W) = W 不被任何超串覆盖的次数（v1 已有）
  
  归属分布：
    P(∅)     = independent / count          （独立身份）
    P(Sᵢ)    = cover_count(W, Sᵢ) / count   （从属于 Sᵢ 的身份）
  
  结构归属熵：
    SBE(W) = - [ P(∅)logP(∅) + Σ P(Sᵢ)logP(Sᵢ) ]
```

这个指标和复合熵**完全正交**：
- 复合熵看的是**线性文本中的左右邻接字**
- SBE 看的是**层级词汇结构中的超串身份**

### 判据设计（替代 pos-fixed）

对于复合熵 < 0.5（将被过滤）的词，增加一层**结构豁免**：

| 条件 | 判定 | 典型例子 |
|------|------|----------|
| **P(∅) ≥ α**（如 0.8） | **强独立** → 豁免保留 | `什么鬼`、`一人之下`、`吞噬星空`（几乎总是独立出现，是结构顶端） |
| **P(∅) < α 但 SBE ≥ β**（如 1.5） | **弱独立但分布广** → 豁免保留 | `世界`、`长生`、`都市`（常被覆盖，但覆盖它的超串极多：完美世界、我的世界、长生修仙、都市传说……） |
| 否则 | 真依附 → 滤除 | `之魂`、`我能`、`诸天之`（要么被焊死在少数模板里，要么独立率不足且超串单一） |

## 为什么这比 2.1.16 更接近理想模型？

### 1. 假设更内禀

- **2.1.16**：需要假设「标题末尾的空/PUNCT 不代表依附」——这是针对**语料格式**（一行一个标题）的假设
- **SBE**：只需要假设「结构顶端的词是完整词汇单元」——这是针对**语言结构**的假设，对连续文本、标题文本都成立

### 2. 和 2.1.11 的哲学一致

2.1.11 的理想是：**一个词是否成词，只看它对外界的自由度**。  
SBE 并没有引入外部规则，而是把 v1 的 `independent`（二元判据：≥1 保留）升级为**连续的结构自由度指标**，和复合熵形成**双信号并联**：

```
v1 时代：independent（结构） → 串联 → 复合熵（邻接）
v2.1.11：复合熵（邻接）单信号
新方案：复合熵（邻接） + SBE（结构） 双信号正交融合
```

### 3. 预期能救回的案例

从文档中的错题集看，这些 2.1.11 的误杀应该能被 SBE 救回：

| 词 | 2.1.11 命运 | SBE 预期 | 原因 |
|----|------------|----------|------|
| `什么鬼` | 误杀（右熵 0.44） | ✅ 保留 | P(∅) 高，强独立 |
| `一人之下` | 误杀（左熵 0） | ✅ 保留 | P(∅) 高，强独立 |
| `完美世界` | 误杀 | ✅ 保留 | P(∅) 可能中等，但超串分散（完美世界、我的世界……） |
| `重燃` | 误杀 | ✅ 保留 | 结构顶端，独立率高 |
| `从零` | 基线误留 | ❌ 滤除 | P(∅) 低（0.1），超串单一（从零开始），不满足豁免 |

### 4. 和 2.1.16 的关键差异

2.1.16 的 `pf=0.80` 能救回 `什么鬼`，是因为它的右邻 96% 是空/PUNCT。  
SBE 能救回 `什么鬼`，是因为它在候选池 DAG 中是一个**源点**（source）——没有入边，不被任何更长候选词覆盖。

两者的救回路径不同：
- 2.1.16：「右邻空多 → 不是真依附 → 忽略右侧」
- SBE：「结构顶端 → 不是真依附 → 豁免」

**SBE 的判定不依赖「空/PUNCT/句末」这些表层特征**，即使未来语料不是标题格式（比如连续正文），它依然有效。

## 实施建议：如何在 2.1.11 上落地

### 第一步：修改 BFS 生长，记录超串覆盖分布

当前 v1 的 BFS 只记录了两个数：
```python
count        # 总出现次数
independent  # 不被更长词覆盖的次数
```

你需要扩展为：
```python
cover_map = {}  # {super_word_id: cover_count}
```

在扫描语料时：
- 对每个出现位置，找出覆盖该位置的所有候选词（或至少最长的几个）
- 如果词 W 的某次出现被超串 S 覆盖，则 `cover_map[S] += 1`
- 同时 `independent` 的逻辑保持不变（没有任何超串覆盖时才 +1）

### 第二步：在过滤阶段计算 SBE

在 2.1.11 的 `min-ent` 判据之后，对将被过滤的词（CE < 0.5）加一层：

```python
if compound_entropy >= 0.5:
    keep = True
else:
    p_indep = independent / count
    if p_indep >= ALPHA:  # 如 0.8
        keep = True  # 强独立豁免
    else:
        # 计算被覆盖部分的超串熵
        h_super = entropy(cover_map.values())  # 只算被覆盖的部分
        if h_super >= BETA:  # 如 1.5
            keep = True  # 弱独立但超串分散
        else:
            keep = False
```

### 第三步：网格调参

和 2.1.11 的 `me`/`mr` 一样，你需要对 `ALPHA`（强独立阈值）和 `BETA`（超串分散阈值）做网格扫描。

预期：
- `ALPHA` 在 0.7~0.9 之间是甜点。太低会放过 `我能`（P(ind)≈0.5），太高会漏救 `世界`（P(ind)=0.13）
- `BETA` 在 1.0~2.0 之间。保护像 `世界`、`长生` 这类「被覆盖多但超串杂」的真词

## 风险与注意事项

### 1. 短词的 SBE 天然偏高
像 `之`、`的` 这种语法字，如果它们在候选池中，会被几乎所有超串覆盖，SBE 极高。但：
- v1 的 `len ≥ 2` 已经过滤了单字
- 对于 `我的`、`这个` 这类 count 极高的句法碎片，它们确实 SBE 高、复合熵也高——**三个信号都滤不掉它们**。这正是文档末尾提到的「句法停用词表」盲区，SBE 解决不了，需要第四维度。

### 2. 和复合熵的相关性
如果 W 的复合熵高（左右邻居都自由），它的 SBE 通常也高（超串多）。两者不是完全独立的，但**正交性足够**：
- `什么鬼`：复合熵低（句末），SBE 高（结构顶端）→ 正交 ✅
- `世界`：复合熵高，SBE 高 → 两者一致 ✅
- `之魂`：复合熵高（2.1.11 其实没滤它），SBE 低 → 如果未来复合熵阈值提高，SBE 可以补刀

### 3. 计算开销
构建超串覆盖关系需要 O(N² × L) 的字符串包含检查（N=7150, L≈10），约 5000 万次操作。在 Python 中可能稍慢，但完全可以接受。如果追求性能，可以用 Trie 或后缀数组加速。
