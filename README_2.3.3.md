# 2.3.3-cohesion-poset 设计说明与结论

> 在 **2.3.1-cohesion（凝固度基线）** 上开的、与 2.3.2-ami 平行的分支。
> 本次只加 **「词本身的偏序关系」**（独立频次占比 `indep`）进凝固度信号体系；
> **补集偏序**（`2.4.2` RSR 方向）留作后续版本，本次不做。

---

## 1. 动机：凝固度（PMI）的漏网

`2.3.1` 用凝固度 `cohesion = min_split PMI` 作为第二信号（闸门 `coh ≥ 1.5`），
有效清掉了「内部字间松散」的词缀碎片（之巅/我能/之子）。但仍有一类漏网：

- **强搭配碎片**：`我只 / 聊天 / 我真 / 罗之` —— 它们内部某切分点 PMI 不低
  （因为半段本身也是高频词），凝固度门放不过；但它们本质是「固定搭配的半截」，
  从来不**独立成词**，总被某个更长真词完整包裹（如 `聊天` ⊂ `聊天室`、`我只` ⊂ `我只想`）。

用「外部统计（SPE/RSR）推断内部成词性」必然撞墙（这是 `2.4.2` RSR 失败的根因，
同构于「独立率陷阱」）。正确的补刀是引入**词本身的偏序**：一个词 W 被更长候选
词完整包裹的程度，直接反映它是否只是别人的「零件」。

---

## 2. 第六信号：`indep`（词本身偏序 · 独立频次占比）

```
indep(w) = (count(w) − covered(w)) / count(w) ∈ [0, 1]

covered(w) = Σ 被更长候选词(超词) 完整包裹的加权出现次数
包裹定义：存在更长候选 s，其某次出现 [sp, sp+ls) 满足 sp ≤ p 且 sp+ls ≥ p+lw 且 ls > lw
```

- **强搭配碎片** ≈ 0（`我只/聊天/我真/罗之` 几乎每次出现都嵌在更长真词里）
- **真词** ≥ 0.13（`世界 0.129 / 开始 0.280 / 首富 0.538`）
- **词缀碎片**（`我的/联盟之`）因超词稀疏仍偏高 → 留补集偏序版 `2.4.2` 处理

实现上零成本复用 `scan_and_grow` 已算出的候选词与位置表：建「起始位置→候选词」倒排
`pos_start`，对每更长候选 s 的每次出现标记其内部被包裹的子候选（去重 `covered_occ`），
再折算 `indep`。候选元组由 6 字段扩为 7：

```
(word, count, independent, binding, compound_ent, cohesion, indep)
```

---

## 3. 闸门：凝固度 × 偏序 联合门

`process_corpus` 的凝固度门升级为 **联合门**（两者取 AND，单字/超长词直接放行）：

```python
ok_coh = (min_cohesion <= 0) or (c[5] >= min_cohesion)
ok_ind = (min_indep    <= 0) or (c[6] >= min_indep)
保留 ⇔ ok_coh and ok_ind
```

CLI 新增 `--indep`（默认 0.0 关闭）与 `--indep-super-min`（覆盖者最小加权次数，默认 1）。

## 5. 结论：性能提升与版本区间

**性能提升**：在凝固度基线上零成本加一层「词本身偏序」信号，以 **零真词误杀** 的代价，
清掉凝固度（PMI）无法识别的 7 个强搭配碎片（`我只/聊天/我真/罗之` 等）。
这是「用内部偏序推断成词性」对「用外部统计推断成词性」的正交补强——方向正确，
且不与 SPE/RSR 同构撞墙。

**版本区间定位**：

| 版本 | 产词数 | 谱系 |
|---|---:|---|
| v211 | 5865 | 早期（仅熵+binding） |
| v216 | 5877 | 早期调参 |
| v217 | 5156 | 凝固度(PMI)基线 |
| **2.3.3** | **5149** | **凝固度家族（仅比 v217 低 7 词）** |
| 2.4.1-spe | 5895 | SPE 纵向包含秩序家族 |
| 2.4.2-poset | 5889 | SPE + RSR 补集偏序家族 |

**2.3.3 = 5149，明确落在 2.3.x 凝固度家族区间内**（与 v217 仅差 7 词），
与 2.4.x 的 SPE/RSR 家族（5865~5895）是**完全不同区间**——
前者在「收缩误杀碎片」，后者在「用纵向/补集偏序扩召回」，目标与机理都不同。
