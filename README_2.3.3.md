# 2.3.3 — 词本身偏序独立频次（2.3.1 凝固度后继，与 2.3.2-ami 平行）

> 分支：`2.3.3-cohesion-poset`（从 `2.3.1-cohesion` 开出，与 `2.3.2-ami` 平行）。
> 把"词本身的偏序关系"加进凝固度门：在 2.3.1 的「凝固度(PMI)」之外，新增第六信号
> **偏序独立频次 `indep`**，作为凝固度门的 AND 条件，专清「凝固度很高、但其实是强搭配碎片」的漏网。
> 补集偏序（2.4.2 RSR 方向）留待下一版。

## 一、动机：2.3.1 的漏网不是凝固度能救的

2.3.1 凝固度门（coh≥1.5）的正确漏网 = **强搭配碎片**：

| 词 | coh(PMI) | ent | 实为 |
|---|---|---|---|
| 我只 | 3.73 | 1.26 | 碎片（我+只） |
| 聊天 | 6.03 | 0.48 | 碎片（群聊/聊天群） |
| 我真 | 3.81 | 1.08 | 碎片 |
| 罗之 | 3.10 | 0.37 | 碎片 |
| 界的 | — | — | 碎片 |

这些词内部字间 PMI 很高（"我"和"只"在这语料里确实常绑一起），凝固度门放行——
但本质上它们是「被更长候选词包裹的嵌套碎片」，不是独立成词。

> 注：000 层真词（迪迦/康熙/首富/庆余年…）coh 全在 6~13，死在**熵门**而非凝固度门，
> 本分支（过滤器）救不了它们——救 000 层是 2.4.x SPE 方向的事。

## 二、信号定义：`indep`（偏序独立频次占比）

对候选词 w，设 `covered(w)` = 被任意更长候选词 s 包裹的出现权重（按位置精确统计，非近似）：

```
indep(w) = (count(w) − covered(w)) / count(w)   ∈ [0, 1]
```

- 强搭配碎片（我只/聊天/我真/罗之）几乎总嵌在更长词里 → `indep ≈ 0`；
- 真词（世界/开始）大量独立出现 → `indep ≥ 0.13`；
- 词缀型碎片（我的/联盟之）超词稀疏未被候选 → `indep` 仍高（留待补集偏序下版）。

实现：BFS 后建「位置→候选词」倒排，对每个更长候选 s 的每次出现，标记其内部子候选为被覆盖，
每个子候选的每次出现只计一次覆盖权重（去重）。零成本复用凝固度已有的候选/位置结构。

## 三、闸门（route B，与计划书一致）

多字候选需 **凝固度达标 ∧ 偏序独立频次达标** 才保留：

```
keep ⟺ len(w)<2  OR  (coh ≥ 1.5  AND  indep ≥ ε)
```

单字无内部绑定概念→放行；补集偏序型碎片（我的/联盟之）因超词稀疏未被候选→indep 仍高→本门暂不滤。

## 六、结论：性能提升与版本区间

1. **性能提升（vs 2.3.1）**：在零真词误杀前提下，额外滤掉 7 个「凝固度很高但实为强搭配碎片」的漏网
   （界的/游之/真不/我只/我真不/我真/是大），输出更干净；高频误伤不增，000 层召回不变（=0）。
2. **版本区间定位**：2.3.3 = **5149**，落在 **2.3.x 凝固度家族**，**仅比 v217(5156) 低 7 词**，
   是 2.3.1 的一个干净精炼版；与 **2.4.x SPE/RSR 家族（5865~5895，走"救援 000 层"方向）完全不同区间**。
3. **信号有效性**：`indep`（词本身偏序）精准命中强搭配碎片，是真正可用的第六信号；
   反观 2.4.2 的 RSR（补集偏序）测错变量（补集常见字）失败——印证「词本身偏序」是凝固度方向的正确补充。
4. **已知局限**：① 救不了 000 层（过滤器非救援器）；② 词缀型碎片（我的/联盟之/这个）
   超词稀疏未被候选→indep 仍高→逃逸，需补集偏序（下一版）或功能字词典解决。
