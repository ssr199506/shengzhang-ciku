### 0.3 先看一遍"分和指标"（后面都用得上）

每个配置会输出一行：

```
 5149 keep36/37 filt 1/25 000 0/15 frag 4/18 coll159 | A=0.645 B=0.440 C=0.247
```

| 片段 | 含义 | 好方向 |
|---|---|---|
| `5149` | 最终保留词数 | 适中（几千） |
| `keep 36/37` | 37 个"应保留词"里保住了 36 个 | 越大越好 |
| `filt 1/25` | 25 个"应滤除词"里**漏进来** 1 个 | 越小越好 |
| `000 0/15` | 15 个干净真词里召回了 0 个 | 越大越好 |
| `frag 4/18` | 18 个碎片里漏进来 4 个 | 越小越好 |
| `coll 159` | 疑似误伤的高频词数 | 越小越好 |
| `A=0.645` | **A 权重总分**（保守口径，最常用） | 越大越好 |
| `B=0.440` | B 权重总分（均衡口径） | 越大越好 |
| `C=0.247` | C 权重总分（召回口径，看重 000） | 越大越好 |

分数口径说明（三套权重代表三种产品偏好）：
- **A 保守**：宁可少召回，也要干净（keep 和 filt 各占 0.35）。
- **B 均衡**：keep/filt/召回各占 0.25。
- **C 召回**：看重救回真词（recall 占 0.45），会牺牲干净。

> **记住一个规律**：C 权重跑出来的最优参数，通常比 A 权重更"激进"（词更多、碎片更多）。这不是 bug，是侧重点不同。

## 2、Phase 1：单参数敏感性（粗跑 → 精跑）

**目标**：找出每个参数"调多少对结果影响多大"，锁定值得细看的区间。

### 2.1 全参数粗跑（大步长）

```bash
python 调参产物/sens_single.py
```

预计耗时几秒。**预期输出**（真实样例）：

```
===== 敏感性排序（score_A 跨度，越大越敏感）=====
  min_cohesion         ΔA=0.3518  最优=2.0    scoreA=0.6412
  min_indep            ΔA=0.2593  最优=0.2    scoreA=0.6329
  min_ent              ΔA=0.1805  最优=0.5    scoreA=0.6449
  spe_rescue           ΔA=0.1592  最优=0.0    scoreA=0.6449
  bind_thresh          ΔA=0.1334  最优=1.0    scoreA=0.6449
  ...
  rsr_mode             ΔA=0.0     最优=mean   scoreA=0.6449
```

产物：`调参产物/sens/*.csv`（每参数一张表）+ `sens/summary.csv`。

### 怎么读（判断要点）

1. **ΔA 越大越敏感**。最敏感的是 `min_cohesion`（Δ0.35）、`min_indep`（Δ0.26）、`min_ent`（Δ0.18）。这三个是主旋钮。
2. **ΔA≈0 的参数**（`rsr_mode`、`min_super_cnt`、`cohesion_max_len`）不用管，保持默认。
3. **"最优"列**如果和当前推荐重合（如 `min_ent 最优=0.5`、`spe_rescue 最优=0.0`），说明当前值已经是局优，别动它。
4. 粗跑的"最优"只是个粗格子，**真正的最优可能在两个粗格之间**——这就是下一步精跑的原因。

### 2.2 精跑可疑区间（细步长）

对 ΔA 大、且"最优"旁边有上升趋势的参数，缩小范围细跑。

**怎么定区间**：粗跑最高分那个值，往两边各放 1~2 个粗格。
例：`min_cohesion` 粗跑格是 `0,2,4,6,8,10`，最高分在 2 附近 → 精跑区间取 `0 ~ 4`。

```bash
python 调参产物/sens_single.py --param min_cohesion --lo 0 --hi 4
```

**预期输出**（真实样例）：

```
  min_cohesion=1.0      5367 keep36/37 filt 3/25 000 0/15 frag 5/18 coll119 | A=0.614 ...
  min_cohesion=1.5      5149 keep36/37 filt 1/25 000 0/15 frag 4/18 coll159 | A=0.645 ...
  min_cohesion=2.0      4905 keep36/37 filt 1/25 000 0/15 frag 4/18 coll221 | A=0.641 ...
```

**判断**：峰在 **1.5**（1.0→1.5 大涨，1.5→2.0 开始回落）。确认当前定档 coh1.5 正确。

对 `min_indep` 也照做（粗跑网格没有 0.05，粗跑看起来峰在 0.2，但真正峰可能在 0.05~0.1 之间）：

```bash
python 调参产物/sens_single.py --param min_indep --lo 0 --hi 0.4
```

### 记录
每跑一个参数，把输出贴到运行日志，并记一句结论（如"coh 峰在 1.5，当前值正确"）。

## 3、Phase 2：极端参数边界测试

**目标**：把每个参数推到最狠，看会不会崩、会坍缩多少——圈出"危险区"。

### 怎么跑
```bash
python 调参产物/extreme_bound.py
```

### 预期输出（真实样例）

```
  min_cohesion=10.0    331 keep 3/37 ... ⚠️ 坍缩6% 删4818
  min_ent=2.0         2266 keep27/37 ...   坍缩44% 删2883
  bind_thresh=0.5     3671 keep24/37 ...   坍缩 删1478
  spe_rescue=2.0      5149 ... 删0
```

### 怎么读
- 带 **⚠️** 的是危险区：`min_cohesion` 推到 10 只剩 331 词（keep 全灭）——**coh 千万别设太大**，clamp 上限建议 ≤4。
- `spe_rescue=2.0` 删 0 个词：说明 SPE 救援在当前数据上基本不干活（阈值设太高没有词够格）。
- 产物 `extreme/removed_*.csv` 是每个极值下被删的词清单，可人工翻看"哪类词先牺牲"。

### 记录
把报告贴进运行日志，记一句："危险区 = coh>4、ent>1.5、bind<0.7"（以实际为准）。

## 4、Phase 3：一阶差分坐标下降（核心）

**目标**：自动找最优。每个参数"动一下看分数变化"，哪个方向加分就动哪个——这就是借鉴反向传播的思想。

### 4.1 三套权重各跑一遍

```bash
python 调参产物/tune_diff.py --weight all
```

### 预期输出（真实样例，C 权重）

```
[C] 起点 score=0.2472  cfg=me0.5 coh1.5 indep0.05 spe0 rsr0
  r1 动 ent_merge_ratio→0.45   score=0.4415 (Δ+0.1943)
  r2 动 ent_merge_ratio→0.65   score=0.5138 (Δ+0.0724)
  r3 动 ent_merge_ratio→0.85   score=0.6341 (Δ+0.1202)
  r4 动 min_cohesion→2.0    score=0.6506 (Δ+0.0165)
[C] 收敛 最终 score=0.6506
```

### 怎么读
- 每行是"动了一个参数"：`动 ent_merge_ratio→0.45` 表示把它从 0.25 调到 0.45，分数涨了 0.19。
- **收敛** = 连动 3 轮都没有任何参数能加分了。最终那行的 θ 就是这套权重下的最优。
- A 权重通常第一轮就收敛（说明当前推荐在 A 口径下已经是最优，**诚实记录即可，不用硬凑**）。
- C 权重会往高 `mr`（ent_merge_ratio）走——因为放大候选池能救回真词，C 看重这个。

产物：`调参产物/grad_A.json`、`grad_B.json`、`grad_C.json`（每轮轨迹 + 最终配置）。

### 记录
把三套的最终 θ 和 score 抄进运行日志。

## 5、Phase 4：随机搜索 + 重启（防止只找到局部最优）

### 5.1 随机撒点

```bash
python 调参产物/random_search.py -n 100
```

预计耗时 30~60 秒。**预期输出**：三套权重各 Top5。

### 怎么读
- **A 权重**的 Top1 分数通常 ≤ 0.534，**低于 θ₀ 的 0.645** → 说明 θ₀ 在 A 口径下已是全局优，随机点翻不过去。
- **C 权重**的 Top1（如 `me0 mr0.4 coh8.0 ... 000真10`）会明显超过 θ₀ → 说明 C 口径下另有最优，值得把它当种子继续优化。

### 5.2 用随机 Top 做重启（给差分换个起点）

从 `random_top.json` 里抽一个配置当起点，让差分从它继续爬：

```bash
python -c "import json; t=json.load(open('调参产物/random_top.json')); json.dump(t['C'][0]['cfg'], open('调参产物/start_C.json','w'), ensure_ascii=False)"
python 调参产物/tune_diff.py --weight C --start 调参产物/start_C.json
```

看它还能不能爬得更高。爬不动就说明这就是 C 口径的天花板。

## 6、Phase 5：验证与交付

**目标**：确认调参结果不破坏回归基线，并产出最终配置。

### 6.1 回归验证（红线，必须过）

```bash
python regress.py
```

必须看到 `ALL PASS ✅`（6 个 golden 组合逐词一致 + 金标准 sha 完整 + 60 组扫描对拍）。
**只要调参改的是阈值参数，这步就应该还是绿。如果红了，说明有代码级回归，先查再继续。**

### 6.2 用最终推荐跑真实产物（含词云，人工目检）

以 A 权重推荐（当前 = 5149 配置）为例：

```bash
python -m grow3.cli corpus.csv --title-col 2 --intro-col -1 --ent-merge-ratio 0.25 --min-ent 0.5 --cohesion 1.5 --indep 0.05 --out out_real
```

然后打开 `out_real/title_wordcloud.html` 目检 top 词：
- 应看到书名类真词（吞噬星空/一人之下/世界…）
- 不应看到碎片（我只/联盟之/罗之…）

### 6.3 汇总成报告

在 `调参产物/最优参数报告.md` 里写：
1. 每参数敏感性排序（抄 Phase 1 的 summary）

5. 最终推荐 + 理由 + 相对 5149 的提升表
6. 诚实结论：A/B 口径下 5149 已是全局优（若属实），C 口径下另给激进配置

## 8、常见问题

| 问题 | 原因 / 处理 |
|---|---|
| 词数不是 5149 | 环境/脚本版本不对，回到 0.1 检查 |
| 跑 `regress.py` 红了 | 别继续调参，先报告——可能是代码回归 |
| 某个参数怎么动分数都不变 | 该参数在当前区间是"平台"，跳过它 |
| C 权重结果碎片很多 | 正常，C 侧重召回；交付时以 A 为主，C 仅供参考 |
| 想复现随机结果 | 已固定 seed=42，同一命令结果一致 |
| 产物漏到别处 | 所有脚本只写 `调参产物\` 和 `out_tmp\`，如发现外溢请报告 |
