## 一、项目背景

输入是起点中文网小说的标题 CSV（约 1.5 万条），通过 BFS 字生长算法生成候选词组（字->词->更长词，最大重复判据），目标是输出一个干净的高频词集用于词云展示。

**核心矛盾**：BFS 生长出来的候选词里，混入了大量"寄生词"（如 `之魂`、`之巅`、`剑修`、`聊天`——它们不是独立词，只是总出现在某个固定搭配旁边）。需要一种判据把这些寄生词筛掉，同时保留真正的自由词和书名。

**金标准词集**（用于评分，手动标注）：

- 应保留 37 词：吞噬星空、一人之下、长生修仙、万族、斗破苍穹、诛仙、史记、无限恐怖、鬼灭、苟在、之主、之王、世界、长生、凡人、修仙、都市、系统、巅峰、重生之、人在木叶、全职法师、风云、无敌、直播、网游、神豪、荒古、重生、战神、天才、玄幻、末世、奶爸、神医、纨绔、重活
- 应过滤 25 词：我能、剑修、剑客、真不是、真没、你管、我只、联盟之、星空之、火影开、无限之、诸天之、之巅、之神、之子、之魂、之开、罗之、世主、生仙、人在斗、影开始、局被、后一、的悠

评分公式：`score = 0.5 × keep率 + 0.5 × filt率`

## 三、核心算法详解

### 3.1 整体管线

```
CSV 标题列
  → clean() 清洗（非 CJK→PUNCT 哨兵）
  → build_corpus() 去重加权、SEP 拼接
  → BFS 字生长（最大重复判据）
  → 独立出现次数（independent: 不被更长词覆盖的次数）
  → 复合熵（compound_entropy: 左右邻居分布的 min 信息熵）
  → 位置固定度豁免（pos-fixed: 句首/句末词的特殊保护）
  → 闸门过滤（bind + min-ent + pos-fixed）
  → 输出词频 CSV + 词云
```

### 3.2 每个出现有且只有一个邻居：三类互斥

每个词的出现位置有一个**左邻字符**和一个**右邻字符**，**三者互斥、和为总次数**：

| 类型 | 符号 | 定义 | 参与熵？ | 算作"有邻居"？ | 输出？ |
|---|---|---|---|---|---|
| **汉字** | 具体字 | CJK 字符(U+4E00-U+9FFF) | 是，每个字独立计数 | **是** | 是 |
| **符号** | `\ue000` (PUNCT) | 所有非 CJK 字符（标点/空白/数字/字母）折叠为同一哨兵，逐字计数 | 是 | **否** | 否 |
| **空** | `\x00` (SEP) | 串首/串尾/SEP 边界——该位置不存在邻居 | 否 | 否 | — |

举例说明（`什么鬼` 在标题语料中，计次 23）：
- 右汉字：仅 `上` 出现 1 次 → 1 种汉字，1 次
- 右符号：PUNCT 10 次（标题末尾的标点）
- 右空：12 次（标题最长词，右边无字）
- 合计：1 + 10 + 12 = 23 ✓（三者和 = count）

### 3.3 复合熵的计算流程

```
对于候选词 w，已知：
  l_cjk = [左 汉字邻居的加权次数...]   (如 [21] 表示左汉字21次)
  r_cjk = [右 汉字邻居的加权次数...]
  l_punct = 左 PUNCT 加权次数
  r_punct = 右 PUNCT 加权次数
  count_w = 该词总出现次数

常量：
  ENT_MERGE_RATIO = 0.25    （合并触发比）
  ENT_MIN_DATA = 3           （数据不足豁免阈值）
  POS_FIXED_THRESHOLD = 0.80 （位置固定度豁免阈值）
```

**判定流程（7 步决策树）**：

```
Step 0: 计算中间量
  l_full = l_cjk + ([l_punct] if l_punct>0 else [])   ← 左完整分布（含 PUNCT）
  r_full = r_cjk + ([r_punct] if r_punct>0 else [])   ← 右完整分布
  l_han = sum(l_cjk)          ← 左汉字总次数
  r_han = sum(r_cjk)          ← 右汉字总次数
  l_non = l_han + l_punct     ← 左非空次数（去掉边界后）
  r_non = r_han + r_punct     ← 右非空次数
  l_empty = count_w - l_non   ← 左空次数
  r_empty = count_w - r_non   ← 右空次数

Step 1: 位置固定度豁免（pf=0 则跳过此步）
  l_fixed = (l_empty+l_punct)/count_w >= POS_FIXED_THRESHOLD
  r_fixed = (r_empty+r_punct)/count_w >= POS_FIXED_THRESHOLD
  → 两侧都固定：熵=-1.0（豁免）
  → 仅左固定：忽略左侧，走单侧右逻辑 → Step 5b
  → 仅右固定：忽略右侧，走单侧左逻辑 → Step 5a

Step 2: 两侧都无汉字邻居？
  l_han==0 AND r_han==0 → 熵=-1.0（豁免，纯独立标题）

Step 3: 仅左有汉字？
  r_han==0 → 走单侧左逻辑 → Step 5a

Step 4: 仅右有汉字？
  l_han==0 → 走单侧右逻辑 → Step 5b

Step 5a: 单侧左逻辑
  l_non < ENT_MIN_DATA(3) → 熵=-1.0（左侧数据太少，不足以判断）→ 豁免
  否则 → 熵 = H(l_full)（以 2 为底的信息熵）

Step 5b: 单侧右逻辑
  r_non < ENT_MIN_DATA(3) → 熵=-1.0 → 豁免
  否则 → 熵 = H(r_full)

Step 6: 两侧都有汉字邻居
  少侧 = min(l_non, r_non), 多侧 = max(l_non, r_non)
  if 少侧/多侧 < ENT_MERGE_RATIO(0.25):
    熵 = H(l_full + r_full)     ← 合并两侧计算
  else:
    熵 = min(H(l_full), H(r_full))  ← 取更僵化一侧
```

> **为什么用 min(左熵, 右熵)？**
> 如果一个词左侧始终跟"群"（`聊天群`）、右侧始终跟"天"（`聊天群`），左边熵高（自由接字多）但右边熵为 0（只接固定的"群"），说明这个词依附在另一侧上——**不是独立词**。min 保证了"两边只要有一边依附"就判依附。低熵在左还是在右等价。

### 3.4 位置固定度豁免的设计动机

在 CSV 标题语料中，词出现在 run 首/末的概率天然高——句子就是一行。一个词 95% 的右侧都是空/PUNCT，不代表它"依附"在什么东西上——只是它恰好总在句末出现。

因此：**位置固定词的单侧低熵是"位置使然"而非"依附证据"**，应对该侧豁免、只看另一侧。

算法：
```
某侧"无汉字邻居"占比 = (空次数 + 符号次数) / 总次数
≥ POS_FIXED_THRESHOLD(0.80) → 该侧"位置固定"
  → 复合熵判据中忽略该侧，只看另一侧
  → 两侧都固定 → 豁免保留(-1.0)
< 阈值 → 按正常流程判定
```

失效模式（阈值与典型词的距离）：

| 词 | 左空+符占比 | 右空+符占比 | pf=0.55 | pf=0.70 | pf=0.80 | pf=0.95 | 性质 |
|---|---|---|---|---|---|---|---|
| 什么鬼 | 9% | **96%** | ✅ | ✅ | ✅ | ✅ | 自由词(句末) |
| 我能 | **98%** | 0% | ✅ | ✅ | ✅ | ✅ | 助动词(句首) |
| 人在斗罗 | 0% | **100%** | ✅ | ✅ | ✅ | ❌ | 真实词(全句) |
| 诸天之 | **75%** | 0% | ✅ | ✅ | ❌ | ❌ | 寄生模板(❌) |
| 联盟之 | **55%** | 0% | ✅ | ❌ | ❌ | ❌ | 寄生模板(❌) |
| 首富 | 31% | **62%** | ✅ | ❌ | ❌ | ❌ | 自由词(❌仍被滤) |

> pf=0.80 是甜点：`诸天之/联盟之` 这类寄生模板的固定度都不足 80%，被正确过滤；而 `什么鬼/我能/人在斗罗` 都能触发豁免。`首富` 是遗憾——22 种邻居太散，固定度仅 62%，无法触发。

## 四、调参经验与技巧（工程精髓）

### 4.1 三参数独立性与正交测试

三个参数各自控制不同的"松紧度"，**不存在一个参数调高就能同时改善所有指标的情况**——每个参数都是"放开一类误判、同时可能引入另一类"的跷跷板。

| 参数 | 默认 | 控制什么 | 升高效果 | 降低效果 |
|---|---|---|---|---|
| `--min-ent` | 0.5 | 熵阈值（主闸门） | 更严：滤掉更多词，可能会误杀真实自由词 | 更松：保留更多词，可能会漏过寄生模板 |
| `--ent-merge-ratio` | 0.25 | 合并触发比 | 更多触发合并（更容易救回低熵侧词） | 更少触发合并（更严格用 min） |
| `--pos-fixed` | 0.80 | 位置固定度豁免阈值 | 更严（只有极高固定度才豁免） | 更松（更多句首/句末词被豁免） |

**交互关系**（80+ 组全网格扫描验证）：

- `pos-fixed` 是**唯一独立有效旋钮**：在 pf∈{0.80, 0.85, 0.90} 区间，me 和 mr 的最优值不变（me0.5+mr0.25），pf 的变化**仅影响"新增/减少"词列表，不影响自由词 vs 寄生词的宏观比例**。
- `min-ent` 和 `merge-ratio` 的**恶化的表现方式不同**：me 偏离最优更多产生"大幅增减"的词数波动，mr 偏离更多产生"边界词归属漂移"。

### 4.2 `--min-ent` 调参指南

**调小 min-ent 会怎样？**

| min-ent | 词数 | filt(应滤25词) | 误伤 | 打开的错误类型 |
|---|---|---|---|---|
| 0.3 | ~5900 | 仅滤 6~8 个 | 极少 | **寄生模板大量复活**：人在斗、影开始、聊天空… 因为寄生词一侧退化（单一邻居）或两侧都多样但都是"模板绑定"——min-ent=0.3 对它们完全无效，BFS 产生的寄生碎片全部幸存 |
| 0.5 (最优) | 5865 | 滤 21 个 | 73 | 剩余 4 个未滤的寄生词（之巅/之神/之子/我只）熵值>1.2，提阈值也滤不掉，属"X之Y"结构（类似之主/之王，用户认可保留） |
| 0.7 | ~5800 | 滤 21 个 | 65~101 | **正常词被误杀**：过滤掉的 65~101 个词不是寄生词而是 count≥5 的真实低频自由词。这些词熵值在 0.5~0.7 之间——低频导致邻据稀疏，熵自然就低，但它们确实是合法词 |
| 0.9/1.1 | ~4300 | 滤 22 个 | 150+ | **误伤暴涨**：大量 count≥5 的正常词因"低频→邻据稀疏→低熵"被误杀。此时过滤量的边际收益为零（filt 仅多+1），但误伤翻倍 |

**结论**：min-ent 的"最优带"是 0.5——寄生集群在 [0.0, 0.3] 区间（BFS 片段=退化邻居=0 熵），把阈值放在 0.5 恰好把他们杀完；大于 0.5 每升高一格都在误杀更多正常低频词，得不偿失。

> **技巧**：熵直方图天然指导 min-ent 定位。生成 `exp/<name>/` 后用 histogram 看一眼——如果 [0.0, 0.3] 是一个巨大柱子（寄生集群），就取 0.5（保障宽松一点）；如果直方图连续无谷，说明不存在天然切断点，min-ent 不适合当前语料。

### 4.3 `--ent-merge-ratio` 调参指南

**调小 merge-ratio 会怎样？**

| mr | 行为 | 影响的词类型 |
|---|---|---|
| 0.10 | 极少触发合并（仅当两侧不空极度不平衡时才合并） | 漏救大量"一侧几乎全空"的自由词，如苟在(13%)、吞噬星空等 |
| 0.20 | 适度合并 | 够用，但误伤仍有 105 个 |
| **0.25 (最优)** | **多救回 32 个正常词，filt 率不变，无误伤增加** | 在"漏滤寄生"和"误救自由"之间最优平衡点 |
| 0.30 | 过于激进，漏滤 2 个寄生词（filt 从 21→19） | 之巅、之魂 这种 min 熵接近阈值（~1.2）的边界寄生也被合并路径救回来 |

**调小 merge-ratio 后，被多滤掉的词**（mr=0.20 vs 0.25 的差异，pf=0.80 下实测）：

mr 从 0.25 降到 0.20 → 词数从 5877 降到 5836 → 多滤 41 个词。这些词都是"有一侧不空少但勉强达到合并条件"的边界自由词——它们的两侧数据虽然不平衡，但信息量其实足够独立判定，不该合并。合并路径相当于用全体邻居分布（两部分拼起来）去对抗一侧的稀疏信号——这比直接丢掉稀疏侧要安全。

**结论**：merge-ratio 不是越大越好。"合并路径"是把两侧邻居揉成一个大分布去算熵——当少侧数据太少时这是合理近似；当少侧数据刚刚勉强够时，合并会掩盖真实依附信息。最优值 0.25 是在这个语料上实测出来的，不一定在其他语料上通用。

### 4.4 `--pos-fixed` 调参指南（最重要）

**这是唯一有效旋钮**——也是这场工程的核心发现。网格扫描证明：在 pf∈{0.80, 0.85, 0.90} 区间，me、mr 的最优组合不变，pf 的变化只是改变"多救几个真实词 vs 保守"。

**调低 pos-fixed 会怎样？**

| pf | 新增 | 新增中的"坏新"(寄生复活) | 评价 |
|---|---|---|---|
| 0.55 | +324 | 5 个（诸天之/联盟之/无限之/火影开/星空之） | 严重泄漏——这些"之X"模板词句首比率 ~55~75% |
| 0.60~0.75 | +85~324 | 3~5 个 | 寄生泄漏逐渐收敛，0.75 仍复活 3 个（诸天之/无限之/星空之） |
| **0.80** | **+12** | **1 个(我能，用户接受)** | **甜点**：多救 10 个真实词（完美世界/重燃/君临/妙手/九星/黑客/魔法师/仙朝/仙医/神诡世界）+ 什么鬼/人在斗罗/我能，诸天之等寄生仍被正确格杀 |
| 0.85/0.90 | +2~3 | 1 个(我能) | 保守版：只救 我能/什么鬼/人在斗罗 |
| 0.95 | +2 | 1 个(我能) | 过严：人在斗罗 漏救（它的固定度=100% 恰好 ≥0.95）、从零没有被修掉 |

**为什么 0.55~0.75 区间是雷区？**

`诸天之` 这类寄生模板在语料中大量作为"诸天之XX"出现——它是典型的"句子开头助词"，左侧无字、右侧自由。它的句首固定度高（~75%），所以低阈值会把它当"位置固定词"豁免。"诸天之"被豁免后，左侧被忽略，只看右侧（自由接字多样性高）→ 高熵 → 保留。

但这不是错的——它与 `我能` 的结构完全一样（语法助词 + 自由搭配）。区别在于**用户意愿**：诸天之被判定为寄生模板（要滤），我能被判定为可接受的助动词（要留）。**这已经超出了纯熵指标能覆盖的范畴，属于语义级偏好。**

> **核心教训**：任何"豁免层"都有"放关"的副作用——保护 `什么鬼` 的同时给了 `诸天之` 豁免证据。降低 pf 阈值是"一刀切"地扩大豁免范围，必须逐词确认被赦免的是否全是你想要保留的。本项目做了**90 组全网格 + 逐词归属表**后才确认 0.80 不是空串。

### 4.5 调参实操流程（推荐 SOP）

```
1. 基线生成: python grow.py input.csv --out exp/base --pos-fixed 0 --min-ent 0 --no-cloud
    → 拿到全量候选集 N 个词

2. 直方图定位 min-ent:
    → 生成一份 me0.0 的输出，统计熵值分布
    → 找寄生集群（通常在 [0.0, 0.3]）与自由词集群（通常在 [1.0+]）的"谷"位置
    → 定一个基准 me（如 0.5）

3. me × mr 粗网格:
    python exp/sweep_pf.py（或手工跑 3×3=9 组）
    → 把 me∈{0.3,0.5,0.7} × mr∈{0.20,0.25,0.30} 跑完
    → 对照金标准算得分，取最高一档作为 me×mr 定档

4. pos-fixed 细调:
    → 在定档的 me/mr 上，跑 pf∈{0.55..0.95, step=0.05}
    → 逐词看新增列表（pf 每降一格的"增量"）
    → 确认没有寄生词泄漏到新增列表 → 取该 pf 为默认值

5. 最终 diff:
    → 最终参数 vs 基线（pf=0），逐词列出"新增/减少"完整列表
    → 所有新增词人工过一遍，确认每个都属于可接受范围
```

## 五、失败实验复盘

### 5.1 独立率保护（2.1.14 / 2.1.15）

**想法**：被熵误杀的自由词往往"独立成段"比例高 → 在熵过滤后，把 independent/count ≥ 0.25 的词恢复回来。

**为什么失败**：
- **97% 的被滤词独立率都 ≥ 0.25**。短 BFS 片段天然拥有高独立率——它们就是"经常能独立成段"，但这不代表它们不是寄生模板（诸天之 75%、无限之 75%、联盟之 38% 都满足）。
- **没有任何阈值能把它们切分开**：阈值扫描 0.25~1.0，最高 score 仅 0.846（< 基线 0.906），且始终漏救 剑修/剑客/之魂 等应滤词。
- **数学恒等式**：两种顺序（前置豁免 vs 后置恢复）的留存集合恒等 = {bind 通过 AND (熵通过 OR 独立率≥阈值)}，顺序无关。

**本质教训**：独立率这个信号在 BFS 片段上**没有区分力**——"独立成段"对于短词是常态而非特征。

### 5.2 用户矩阵方案（2.1.13-matrix）

**想法**：2×3 矩阵（左/右 × H汉字/P符号/E空），派生 Total/Imbalance/Indep_Ratio 三个指标联动判据。

**为什么失败**：
- **independent 是"不被更长词覆盖"计数，不是"自由词"指标**。`世界`(34/263=13%)、`长生`(47/124=38%) 的独立率天然低——它们总作为"完美世界"/"长生修仙"的组成部分出现，但它们本身是完全合法的独立词。
- **方案里示例数据不准确**：`我能` 预期 independent=30/86=35%、实际 30/59=50.8%，刚好跨过 50% 豁免门槛——用户基于错误数据设计，实测时数据不符。
- **Total<8 豁免会放行短片段寄生**：`剑修`(3)、`剑客`(3) 均满足 Total<8 → 被豁免保留 → 这正是要滤掉的寄生词。

**本质教训**：indep 计数不适合作为"自由词"的直接判据——它测量的是"被覆盖比例"，而高覆盖词里既有真正的自由词（世界、长生）也有真正的寄生词（剑修）。

### 5.3 PUNCT 全局空化（2.1.12-punct-empty）

**想法**：把 PUNCT 在熵计算中完全视为空（不计入分布、不参与合并决策）。

**为什么失败**：
- **结构性矛盾**：`一人之下`（左汉字 2+2=4，右侧多样 → min=0 需合并救）和 `我能`（左汉字 1+50=51，右侧多样 → 应 min 滤）的**不空比例绑定**。PUNCT 空化后，两人之不空比都在 ~4%，恰好卡在 merge-ratio 的同一侧——救了前者必放后者。
- **主分支之所以能分开，正因 PUNCT 参与不空**：`我能` 的左 PUNCT×26 让不空比例到 46%（>25% 不触发合并）→ min(左0,右4.8)=0 → 正确滤除。

**本质教训**：PUNCT 作为"邻居信号"是功能性的，不是因为它是字，而是因为它能**提供不对称信息**——PUNCT 密集侧天然不等于"有语义邻居"，但它能帮助区分"一侧全空"和"一侧有语义信息"。

### 6.4 核心经验

1. **单标量指标的局限**：复合熵 = min(H左, H右) 是一个标量——用"邻居分布的僵化程度"去近似"词是否是依附词"。这在大部分情况下有效，但有两类系统性失效：
   - **句首/句末词的"一侧全空"被等同于依附**（位置固定度豁免解决）
   - **独立词因低频→邻据稀疏→低熵**被误杀（当前仅靠 ENT_MIN_DATA=3 豁免最极端的，低频频发仍有误伤）

2. **豁免层必有副作用**：任何"在某些条件下放宽判定"的机制，都是打开了过滤器的后门。必须逐词验证被放过的每一个词——不是看宏观指标，是一个个词地看新增列表。

3. **参数间存在锁定效应**：一旦 me/mr 被定档，pf 就是在"这个锁定组合"上的微调——它不会颠覆 me/mr 达成的过滤/保留大格局，只会增减个位数词。所以粗调先定 me/mr，细调用 pf。

4. **金标准词集是绝对必需品**：没有 keep 36 + filt 25 这套参照系，调参就是盲人摸象。看不到 score 的变化方向，不知道是"救了想要的"还是"放了不该放的"。

5. **不要在语料不匹配的信号上找区分力**：indep_ratio 失败的根本原因是 BFS 短片段中 indep 本来就不是区分的信号；矩阵方案失败的根本原因是 indep 计数 vs 自由词的映射关系本身就不成立。
