# 生长词库 · 复合熵过滤演进文档

**目标**：从起点中文网标题 CSV（~1.5 万条）中，通过 BFS 字生长算法提取高频词组，并滤除寄生碎片，
保留真正的书名与自由词。

**核心矛盾**：BFS 生长出来的候选词里，混入了大量"寄生词"——它们不是独立词，只是总出现在某个固定
搭配旁边（如 `之魂` 永远跟在 "X之魂" 后面、`聊天` 永远 92% 紧邻 "群"）。需要一种判据
把这些寄生词筛掉，同时保留真正的书名和自由搭配。

---

## 一、算法基础（快速回顾）

BFS 字生长算法产出每个候选词的 5 个基础指标：

```
(w, count, independent, binding, compound_entropy)
```

其中 `independent` 是"不被更长词覆盖的出现次数"。核心创新点在 `compound_entropy`——**复合熵**。

### 每个词的出现有一个左邻和一个右邻，分为三类：

| 类型 | 例子 | 参与熵计算？ | 算作"有邻居"？ |
|---|---|---|---|
| **汉字** | 实打实的 CJK 字符 | 是，按字计数 | **是**（这是"依附判定"的唯一依据） |
| **符号(PUNCT)** | 标点/数字/字母统统折叠成一个哨兵 `\ue000` | 是，按次数累计 | **否**（符号邻居不表示"有依附对象"） |
| **空(SEP)** | 串首/串尾/SEP 标记 | 否（不存在邻居，不计入） | 否 |

> 三类**互斥且和为总出现次数**。比如 `什么鬼` 出现 23 次，右邻三类分别是：汉字"上"×1、符号(PUNCT)×10、空×12 → 1+10+12=23。

### 复合熵的判定链路

```
某侧"无汉字邻居"占比 ≥ 80%（空+符）？
  → 是 → 该侧是"位置使然"（句首/句末），忽略该侧，只看另一侧

否则进入标准判据：

一侧全空（无汉字、无 PUNCT）→ 该侧忽略，用另一侧算熵
  另一侧数据 < 3 次 → 豁免（信息太少，不能判定依附）

两侧都有汉字：
  少数侧非空 / 多数侧非空 < 25%  → 合并两侧分布，算总熵
  否则                              → min(左熵, 右熵)

最终：熵 < 0.5 → 判为依附词，过滤
```

> **为什么用 min？** 一个词叫"依附"，只要**有一侧**焊死在固定字上就行——`聊天` 右侧 92% 是"群"，
> 即使左侧接字万般自由，它也是"聊天群"的寄生碎片。min 保证了两侧只要一边低即判依附。

## 二、版本演进：问题 → 发现 → 改进 → 新问题

### 2.1.4 — 首次引入复合熵（min 判据）

**做法**：BFS 生长的每个候选词，计算左右邻居的信息熵，取 `min(左熵, 右熵)` 作为依附判据。

**首先暴露的问题**：
标题语料中，词大量独立成段出现在"一行就是一条标题"的模式里。`吞噬星空` 出现 20 次，19 次左邻是
空（在标题开头），1 次左邻是"从"。按照"空不计入熵"的规则，左熵 = H([1]) = 0。右熵正常。
min(0, 1.43) = 0 → **被误杀**。

**根因**："全独立成词"和"焊在固定字上"在 min 判据里**长得一模一样**——都是一侧熵为 0。
`吞噬星空` 的 0 是因为 19/20 是空（独立标题），`剑修` 的 0 是因为永远跟着"我"。
**min 不区分这两者。**

→ 这直接催生了 2.1.6。

---

### 2.1.5 · 2.1.6 — 标点感知 + 合并熵模式

**2.1.5**：引入 PUNCT 哨兵——非 CJK 字符不丢弃，折叠成同一个"特殊汉字"参与熵分布。
意图是让标点提供额外的邻居信号。

**2.1.6**：引入**合并熵**——当一侧邻居数据极少时（少侧/多侧 < 10%），不取 min，而是把
左右邻居揉在一起算总熵。专门针对 `吞噬星空` 这种"只因为独立成词太多导致一侧数据真空"的词。

**合并熵的效果**：

| 词 | 之前(min) | 之后(合并) | 结果 |
|---|---|---|---|
| 吞噬星空 | 0 | 1.64 | ✅ 救回 |
| 一人之下 | 0 | 1.24 | ✅ 救回 |
| 之主 / 之王 | 0 | 4.64 | ✅ 保留（认可） |
| 我能 | 0 | 0.23 | 仍滤（右侧 38 种接字，但左 PUNCT×26 → 不触发合并 → min 滤） |
| 剑修 / 剑客 | 0 | 0 | 仍滤 |

**好在哪里**：从"只看僵化侧"变成"如果数据极度不对称就合并"，救回了大量被 min 误杀的书名。

**2.1.6 留下的问题**：
合并路径只处理了"数据极度不平衡"。但中间情况——双侧数据勉强平衡但一侧低熵——仍然靠 min 杀，
比如 `一人之下` 在合并模式下救回了，但 `什么鬼`（右侧 23 次里仅 1 次汉字"上"、22 次是空/PUNCT）
的右侧不空比例 1/23=4.3% 虽然也应合并，但在 18% 合并比下刚好被挡住。

更重要的是，**2.1.5 的 PUNCT 哨兵引入了一个新 bug**——见 2.1.7。

---

### 2.1.7 — 修正：PUNCT 多算成"真实邻居"

**问题发现**：`长生修仙` 这个纯独立标题（每次出现左右都是"空/符号/串首串尾"），在 2.1.5 中
被踢出豁免、进入统计层 → 熵 = 0 → 被滤。

**根因**：2.1.5 把 PUNCT 算成了"真实邻居"。`长生修仙` 右邻确实有 PUNCT（标题末尾的冒号），
但 PUNCT 邻居 ≠ 有义邻居。**功能上"标点参与了"不代表"标点该被当成依附证据"。**

**修正**：PUNCT 只参与熵分布（提供统计信号），**不作"是否有真实邻居"的判定**。
豁免判定只看纯 CJK：两侧皆无汉字 → 豁免(-1.0)。

**效果**：`长生修仙`/`人在木叶`/`全职法师` 等纯独立标题全部恢复 -1.0 豁免保留。
这次修正把 2.1.5 埋的雷排掉了，但也暴露了 2.1.6"合并熵"的另一个盲区——见 2.1.8。

---

### 2.1.8 — 修正：一侧纯无效就忽略整侧

**问题发现**：`万族`（总在句首出现——左邻 100% 是空）因为左边全是空，按 2.1.6 的逻辑：
"空不计入熵"→ 左邻一整个空 → 左侧被压缩成"单一邻居"→ 左熵 0 → min(0, H右) = 0 → **被滤**。

**用户指出这是 bug**：如果一侧全是无效数据，那根本不能说"这一侧依附"——
那是**没数据**，不是依附证据。

**修正**：一侧 100% 空（无汉字邻居）→ 忽略该侧，只看另一侧。
`万族`：左全空 → 忽略 → 只看右侧（邻居 5 种）→ 熵 2.0 → **保留** ✅

**但引入的新边界问题**：`一人之下` 左邻 21 次中只有 2 次是汉字"从"，19 次是空/PUNCT。
2 次"有汉字" → 不算"全空" → 按正常流程：左仅 1 种汉字 → 左熵 0 → min(0, 1.24) = 0 → **滤**。

**为什么不能同时救它**：2 次汉字正好打碎了"一侧全空→忽略"的保护——它不是全空，它只是**几乎全空**。
而合并路径需要少/多 < 25%：左侧汉字 2 次，右侧汉字 4 次 → 比例 50%，远不触发合并。

→ 这为 2.1.10 的"位置固定度"概念埋下了伏笔。

### 2.1.10 — 邻居三态重构 + clean() 修复

**这是用户反复纠正后终于对齐的定稿版本。核心改进：**

**① 邻居三态规则**明确"符号是一个特殊汉字"——逐字符计数（"LPL史记"→ PUNCT×3 + 史记×2），
参与熵分布、不作"有邻居"判定、输出切掉。

**② clean() 修复**：`PUNCT.join(runs)` 会丢弃首尾孤立符号（"LPL史记"→"史记"，LPL 丢失）。
改为 `re.sub(r'[^\u4e00-\u9fff]', PUNCT, t)` 逐字保留。

**③ 合并触发比从 10% 调到 20%**：`苟在` 左不空 3、右不空 23 → 比例 13%，10% 不触发 → 滤。
用户说 10% 太严，放宽到 20% → 苟在救回 ✅。

**④ 单侧数据不足豁免**：只用一侧算熵且该侧不空 < 3 次 → 豁免。`斗破苍穹` 右仅"之"×1、
`史记` 右仅"之"/"是"各 2 次 — **"数据太少回答不了'归属于谁'，就不滤"** （用户原话）。

**⑤ 合并比 20% 虽然修复了苟在，但放掉了什么鬼吗？**
没有。`什么鬼` 右汉字仅"上"×1+右 PUNCT×10 → 右不空=11，左不空=22 → 比例 50% > 20%，不触发合并 → min 滤。
**什么鬼 在此版本仍被误杀**——这成了后续改进的直接驱动力。

### 2.1.12 — 第一次尝试救"什么鬼"，因结构性矛盾放弃

**触发**：用户拿到 top100 排除词的邻居分布（`exp/excluded_top100.md`），发现 `什么鬼`(#4, cnt=23) 
在真实数据上的分布：右邻 23 次中汉字仅"上"×1、PUNCT×10、空×12。
**这个分布不表征依附——它只是因为高频出现在句末。**

**尝试**：PUNCT 在熵计算中全局视为空（不计分布、不参与合并决策）。

**效果是自毁的**：什么鬼 救回了 ✅，但：
- `一人之下` 被误杀 ❌：左汉字仅"从"×2、PUNCT×17 变空后，2/4=50%（比例反而涨了）→ 不触发合并 → min 杀
- `我能` 复活 ❌：左汉字仅"的"×1、PUNCT×26 变空后，1/59=1.7%（比例骤降）→ 触发合并 → 救回

**结构性矛盾**：PUNCT 空后，一人之下（左 2 汉字、需合并救）和我能（左 1 汉字、需不合并滤）
的命运被锁在了一起——两人的不空比例都极小且接近，任何 merge-ratio 都无法同时满足
"一方触发合并救人"+"另一方不触发合并杀人"。

**教训**：PUNCT 原来在发挥着**功能性作用**——它不是字，但它提供了**不对称信息**：`我能` 的左邻
有 26 个 PUNCT（占比 46%）→ 让不空比例够高（>25%）→ 不触发合并 → min 正确杀掉了它。
一旦把 PUNCT 从"不空"中移除，这种区别力就没了。

→ 方向虽然错误，但证明了**问题不在 PUNCT，而在"单侧近乎空"应该是一个独立的豁免条件**。

### 2.1.13 — 第二次尝试（矩阵方案），在独立率上撞墙

**尝试**：2×3 矩阵（左/右 × H/P/E），派生三个判据联动——Total<8 豁免、Indep_Ratio<0.5 直接滤、
Imbalance>0.8 合并。

**致命缺陷出在 Indep_Ratio**：希望用 `independent/count` 区分自由词和寄生词。但数据说：
- `世界`：independent=34/263=**13%**——因为它是"完美世界"的子串，大部分出现被覆盖。13% 不代表它附属于什么。——步骤 2 直接把它杀了 ❌
- `长生`：independent=47/124=**38%**——同理被覆盖。——杀了 ❌
- `我能`：预期 independent=30/86=35%（应该被步骤 2 杀），实际 30/59=**50.8%**——刚好跨过 50% 豁免。——漏过了 ❌
- `剑修`、`剑客`：Total=3<8 → 步骤 1 豁免 —— 放了 ❌

score 从 0.920 暴跌到 0.735。

**本质教训**：`independent` 测量的是"不被更长词覆盖的比例"——**这是一个关于"这个词多短"的指标**，
不是一个关于"这个词多自由"的指标。短词的被覆盖率自然高于长词，无论它是不是寄生词。
把 independent 当自由词判据用，等于用一个不相关测量去判定是非。

### 2.1.14 · 2.1.15 — 第三条失败路线：独立率后置保护

**尝试**：不改变主判据，在熵过滤**之后**加一层恢复：把 independent/count ≥ 阈值的被滤词复活。

**阈值 0.25 时**：1285 个被熵滤的词里，**1247 个（97%）独立率 ≥ 0.25**。
阈值再拉高（0.55、0.80、1.0），最高 score 仅 0.846，始终比基线 0.906 低 6 分以上。

**2.1.15 换了顺序（前置豁免 vs 后置恢复）**：输出逐字节相同。
因为留存集合的数学形式恒等 = {bind通过 AND (熵通过 OR 独立率≥阈值)}，顺序不影响结果。

**本质教训**：独立率这个信号在 BFS 短片段上没有区分力——短词的独立率普遍高，
因为"经常独立成段"恰恰是 BFS 片段的天性。高独立率包括了你要的字（首富）也包括你不要的模板（诸天之）。
**不对的信号再多也是噪声。**

### 2.1.16 — 位置固定度豁免（当前推荐版）

**核心思路**：既然 2.1.12 证明了"一侧近乎空应该独立豁免"，2.1.8 证明了"一侧全空→忽略整侧"，
那把这两个合起来——**某侧"没有真实汉字邻居"的占比超过阈值，说明这一侧的"空"不是依附结果、而是位置使然。**

```
"无汉字邻居" = 空 + 符号
某侧占比 = (该侧空次数 + 该侧符号次数) / 该词总次数
≥ POS_FIXED_THRESHOLD → 该侧"位置固定"
  → 复合熵判据中忽略该侧，只看另一侧
  → 两侧都固定 → 豁免(-1.0)
```

**为什么必须把"符号"也计入位置固定度？**
如果只计空（SEP），`什么鬼` 右邻 12 次空 / 23 = 52%，远不到 80%。只有计入 PUNCT×10 后，
(12+10)/23=96% 才触发豁免。**符号邻居在这个语境里和空一样——都是"没真正的人/词依附它"。**

#### 逐档扫描（pf=0.55→0.95, me=0.5, mr=0.25）每个档放出了什么/杀了什么：

| pf | 新增数 | 放过的最坏词 | 多杀的正词 | 评判 |
|---|---|---|---|---|
| 0.55 | 325 | **诸天之**(75%)、联盟之(55%)、无限之、火影开、星空之 — 这 5 个是"之X"模板寄生，句首比 55~75% | 无 | ❌ 寄生泄漏 |
| 0.60-0.75 | 85~324 | 诸天之(~75%) 持续存活到 0.75；联盟之 在 0.60 消亡（低于 60%） | 无 | ❌ 仍有泄漏 |
| **0.80** | **13** | **我能**(98%) — 用户接受复活。诸天之(75%)<80% 被正确格杀 | 从零(**修掉基线误留**) | ✅ **甜点** |
| 0.85 | 3 | 仅 我能(98%)，用户接受 | 从零 | ✅ 保守可行 |
| 0.90 | 3 | 同 0.85 | 从零 | ✅ 保守可行 |
| 0.95 | 2 | 仅 我能(98%)，但**人在斗罗(100%) 漏救** | 无 | ❌ 过严 |

> `从零`(cnt=10, ind=1, 熵=1.21) 是一个**意外收获**——基线(pf=0)里它靠合并路径把"空左 + 右'开始'"
> 凑出熵 1.21 被误留。pf=0.80 触发左侧豁免 → 只看右侧 → 右仅"开始"一组 → 低熵 → 正确滤除。
> 它在低 pf 档（0.55~0.75）因为"一侧固定豁免"仍被留，因为合并依然生效；0.80 档才是边界。

#### 为什么 0.80 比 0.85 多救 10 个真实词，却一个寄生都不多放？

这 10 个词是：完美世界、重燃、君临、妙手、九星、黑客、魔法师、仙朝、仙医、神诡世界。

它们的共同特征：都是 **cnt=5、ind≥2 的真实自由词/书名**，在基线被低熵误杀，位置固定度在 80%~85% 
区间（刚好高于 0.80 但低于 0.85）。而寄生模板（诸天之 75%）的位置固定度根本不到 80%—— 
**80% 这条线恰好把"书名/自由词"和"语法模板寄生"的位置特征分开**。

## 三、调参精要（一张表看懂三个参数的"跷跷板"）

每个参数都是一个跷跷板——**一端是"放过寄生词"，另一端是"误杀真实词"。没有免费午餐。**

### 3.1 min-ent：决定"多僵才算僵"

| 调低(松) | 调高(严) |
|---|---|
| ✅ 保留更多真实低频词（邻据稀疏→天然低熵） | ✅ 寄生碎片全部格杀 |
| ❌ **寄生复活**：寄生词一侧邻居单一→熵≈0，阈值 <0.3 时对其完全无效 | ❌ **低频自由词误杀**：cnt=5、邻据不足 3 种的词，熵本就在 0.5~1.0 区间。提高阈值 = 连它们一起杀 |
| me=0.3: filt 仅 6/25（大量寄生逃跑） | me=0.7: 多杀 65~101 个真实词 |

**定位技巧**：跑一次没过滤的候选集，做熵值直方图。寄生集群在 [0.0,0.3]（BFS 片段→退化邻居→熵≈0），
自由词集群在 [1.0,1.5]。阈值放两峰之间的谷——本语料是 0.5。

### 3.2 ent-merge-ratio：决定"少侧多穷才该合并"

| 调低(松=少合并) | 调高(严=多合并) |
|---|---|
| ✅ 严格 min：一侧有依附、另一侧再自由也没用 | ✅ 合并路径救回"一侧近乎空"的真实书名（一侧信息不足，不应只用有信息侧做 min） |
| ❌ **漏救**：一侧几乎全空的真实词被 min 杀（苟在 13%、完美世界 18%） | ❌ **漏滤**：合并把双侧揉在一起 → 总熵比 min 高 → 边界寄生词逃脱（之巅、之魂在 mr=0.30 时被合并路径救） |

**理解合并的本质**：合并路径不是在"说"这个词不依附——它是说"一侧信息太少，不足以为判据"。
所以把两侧都算上报总熵。当总熵够高时，即使某侧确实依附，全视野也认为它够自由。
这是"宁可错杀少，不可错放多"的一种软化——在 merge-ratio 的合理区间内找出最优软化点。

### 3.3 pos-fixed：决定"多少位置占比才算假象"

| 调低(松=更多豁免) | 调高(严=更少豁免) |
|---|---|
| ✅ 多救回句首/句末真实词 | ✅ 严格：不放过任何语法模板 |
| ❌ **之X模板泄漏**：诸天之(75%)、无限之(65%) 等语法助词→句首比例在 55~75% → 满足 <0.80 的阈值 → 被当"位置固定"豁免 ✓ → 只看另一侧→右侧自由→高熵→保留 | ❌ **漏救**：完美世界(82%)、重燃(81%)、人在斗罗(100%) 的位置固定度在 80%~100% 区间，阈值 >80% 就把它们漏了，而 0.95 连人在斗罗也漏 |

> **核心教训**：pos-fixed 是一条"你有多少把握说这个词的低熵只是位置假象"的刻度尺。
> 阈值越低=把握越低=要求越松=放过去的越多。0.80 恰好是语法模板（55~75%）够不到、
> 书名/自由词（80%+）能够到的分界线。

## 四、失败实验的本质教训

三条路线（PUNCT 空化 / 矩阵方案 / 独立率保护）失败，根源各不同，但有一条共同规律：

**不要用一个本身不区分问题的信号去解决问题。**

| 路线 | 信号 | 为什么没区分力 |
|---|---|---|
| PUNCT 全局空化 | 全/空二元 | PUNCT 本是不对称信息源头——空掉它反而抹掉了唯一能分出"我能"和"一人之下"的区别 |
| 矩阵方案 | independent 比例 | independent = "不被更长词覆盖的比例" ≈ "这个词多短"。短的寄生模板（剑修=3 字）和短的合法词（世界=2 字）在这条轴上完全重叠 |
| 独立率保护 | independent 比例 | 97% 的被滤 BFS 片段本来就独立率≥0.25——因为短 ≠ 不独立。高独立率既是真实词的特征，也是短寄生词的特征 |

## 附录：本机环境 git 操作注意事项（血泪教训，2026-08-12）

**背景**：2026-08-12 晚，在 `git stash push -u` 执行中被超时中断后，本仓库 `.git` 一度完全失效（`not a git repository`）。经 jsonl 对话记录 + 回收站 `$I` 信息文件 + 实测验证，根因如下，务必遵守以下约定，避免重演。

### 本机环境的特殊机制（已实测）
1. **`rm`/删除文件 = 移入回收站**（实测：`rm D:/tmp_rbtest/hello.txt` 后回收站出现对应 `$I` 条目）。这不是真正删除，误删可从回收站 100% 找回。
2. **git 的每次写操作都会 unlink/替换 `.git` 内部文件**（清理 lock、更新 refs、写 index），这些删除在本环境全部被重定向到回收站——**所有项目的 git 都因此积累回收站条目**（本仓库 923 条、github-txt-epub 916 条…）。平时无害，但会让 git 操作变慢。
3. **长 git 命令可能超时被中断**：`git stash push -u` 触及大量 `.git` 写操作，每个都慢吞吞走回收站，执行约 2 分钟未完成即被中断（jsonl 证据：`interrupted=true, tool_error_code=8002`），中断时 `.git` 关键文件已被移走 → 仓库失效。

### 约定
1. **高危 git 操作（`git stash -u`、带未提交改动跨分支 `git checkout`）之前，先备份**：
   ```bash
   cp -r .git .git.bak        # 复制不触发回收站，秒级完成
   ```
2. **长 git 操作用后台跑**（`run_in_background`），别让命令等超时被中断。
3. **少用 `git stash`**，改用 WIP 分支 `git commit`，避开 stash 的大规模 `.git` 写。
4. **发现 `.git` 失效先查回收站，别判死刑**：按 `$I` 信息文件解析原始路径（UTF-16LE，找 `盘符:\` 起始），把 `$R` 条目复制回原路径即可恢复。本仓库 8 分支 27 commit 即如此 100% 找回。
5. **远端暂不建立**（任务未完成前不对外推送），所以本地 `.git.bak` 备份格外重要。

## 三版本最终验收评估（2026-08-13，生产视角）

> **结论先行**：此前的 62 词"金标准"**不可信**——它严重高估了凝固度路线、低估了位置固定度路线。改用贴合生产（统计网站标题取名高频词）的维度重新评估后，**位置固定度（自研）与凝固度（成熟 PMI）确实各有千秋，且高度互补**：位置固定度救真词、凝固度清碎片，一个管"别误杀"，一个管"别漏滤"。

### 1. 旧金标准为什么不可信（三个客观证据）

1. **KEEP 集缺真实词**：37 个"应留"词里没有 `完美世界/重燃/什么鬼/人在斗罗/庆余年/君临` 等真实书名/自由词 → 凝固度路线把它们全滤了，金标准一分不扣，只因滤对 `之神/之子` 就加分 → **凝固度被高估**。
2. **FILT 集含主观词**：25 个"应滤"词里有 `我能`，而位置固定度路线按用户意图救活了它 → 救回 5 个真词不加分、反因"我能"扣分 → **位置固定度被低估**。
3. **同构词双标**：`之主/之王`（词缀模式）在 KEEP 加分，`之神/之子`（同构词缀）在 FILT 加分——人为按频次划线，不是客观词性准则。

**用途边界**：62 词打点只适合调参时看"变化方向"，不能当验收标准。

### 2. 实测数据（同一语料：起点标题 7150 候选；同一基准 me0.5+mr0.25；v216 加 pf0.80、v217 加 coh1.5）

| 指标 | main 2.1.11 | pos-fixed 2.1.16 | cohesion 2.1.17 |
|---|---|---|---|
| 输出词数 | 5865 | 5877 | 5156 |
| 硬碎片残留 | 217 | 218 | **113** |
| 旧金标准 score | 0.9065 | 0.8865 | 0.9465 |
| 高频(count≥5)误伤 | 73 | **61** | 198* |

\* 凝固度 198 个"误伤"里多数是该滤的句法碎片（的我/之我/人的/子的），但真误杀也不少（见发现一）。

### 3. 三个关键发现

**发现一：位置固定度（v216）救真词能力最强。** 完美世界、重燃、什么鬼、人在斗罗、九星、仙朝、仙医、黑客、魔法师、妙手、神诡世界、君临 —— **这 12 个真实书名/自由词在 main 和凝固度里全被误杀，只有位置固定度保住了它们**。它把"出现在标题首尾、熵低但其实是位置假象"的真词救回来，是 main/凝固度都没有的能力。

**发现二：凝固度（v217）清碎片能力最强。** 硬碎片残留 113 vs 217，砍掉一半——`之神/之子/我只/联盟之` 这类熵抓不到的中等碎片被凝固度清掉，熵+位置固定度都留不住它们。

**发现三（最有价值）：两者在真实数据上完美正交。** v216 救的词（完美世界/重燃/什么鬼/人在斗罗…）在 v217 里全被误杀；v217 滤的词（之神/之子/我只…）在 v216 里全保留。**救真词的信号不清理碎片，清碎片的信号会误杀真词** —— 一个管召回、一个管精度，恰好互补，这是"双信号组合"最强的实证依据。

**共同盲区**：高频句法碎片（`我的/我在/我是/我有/这个/什么/成了/一个`）count 极高、凝固度也高，熵、位置、凝固度三个信号全部滤不掉，top 高频榜被污染。需**句法停用词表**这一新维度。

### 4. 生产结论（统计网站标题取名高频词）

- **三选一投产：选 v216 位置固定度**——误伤最少（61）、真词保留最多，最贴合"取名高频词"统计。
- **最优解不是三选一，是组合**：v216 位置固定度（救真词）+ v217 保守凝固度（清中等碎片）+ 句法停用词表（清"我的/这个"）。两个自研/外来信号已被证明正交，组合即精度与召回兼得。
- **对自研方法的定位**：位置固定度是从真实误杀数据（什么鬼/完美世界 被熵判死）里悟出的针对性设计，成熟 PMI 方案没有对应物——**不是"追赶成熟方法"，是补了成熟方法的盲区**。代价是碎片清理弱于凝固度。各有千秋，组合即最优。

### 5. 下一步优化方向（已立项，待实施）

**目标：双信号最终版**——把两个已被实测证明正交的信号合入一个版本，让精度与召回兼得。

1. **位置固定度 + 凝固度双信号**：在 v216 位置固定度豁免（救真词）基础上叠加 v217 凝固度闸门（清中等碎片）。实测 v216 救的词 v217 全杀、v217 滤的词 v216 全留，正交互补，组合是唯一能"既保真词又清碎片"的路径。
2. **真词保护（组合的关键细节）**：凝固度阈值必须**保守**（v217 的 1.5 会把 完美世界/重燃/什么鬼/人在斗罗 等真词误杀），且对位置固定度救回的词**豁免凝固度闸门**，避免 v217 的误杀问题在组合里复发。
3. **句法停用词表（三版本共同盲区）**：`我的/我在/我是/我有/这个/什么/成了/一个` 这类 count 极高、凝固度也高的句法碎片，熵/位置/凝固度全部滤不掉——需要第四维度"句法停用词表"从 top 高频榜剔除。
4. **评估口径更新**：弃用旧的 62 词金标准（已被证明高估凝固度、低估位置固定度），改用生产指标验收——**硬碎片残留数、高频(count≥5)误伤数、top 高频词质抽查** 三者并重。
